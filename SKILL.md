# Single-File Game

A game you can email. One `.html` file, opened with `file://`, no server, no network, no
`assets/` folder. Every pixel is drawn by code, every sound is synthesized by code, every map
is generated by code.

The constraint is the point:

- **No asset pipeline** means no missing files, no 404s, no "it works on my machine".
- **No dependency graph** means the artifact is the deliverable — review it, diff it, ship it.
- **Procedural content** means one file can hold a large world at a small byte cost.
- **Offline by default** means it works on a plane, in a classroom, on a USB stick.

## Core rules

These are non-negotiable. Violating one breaks the format.

1. **One file.** All CSS in one `<style>`, all JS in one `<script>` IIFE. No `<link href>`,
   no `<script src>`, no `fetch`, no `import`, no web fonts. A 3D library is pasted inline
   and minified — never referenced. For 3D this is the **default**, not a last resort: "zero
   external assets" means zero runtime requests, not zero library code. See
   `references/asset-craft.md`.
2. **Zero network at runtime.** Works with the network disabled. No telemetry, no analytics.
3. **Art is drawn, not loaded.** Canvas 2D calls, CSS gradients, SVG, or shader-generated
   textures. Bake expensive art once into an offscreen canvas, then blit.
4. **Audio is synthesized.** WebAudio oscillators plus a shared noise buffer. No audio files.
5. **Deterministic where it matters.** Seeded PRNG for maps, palettes and spawn tables so a
   seed reproduces a run; `Math.random()` only for cosmetic jitter.
6. **Failure is a feature.** A global error handler paints a readable banner and keeps the
   page inspectable. Never ship a silent black screen.
7. **Input parity from commit one.** Keyboard, pointer, touch and gamepad resolve into one
   intent object. Mobile is not a later milestone.

## Quality bar

"One HTML file" is the format, not the ambition. A file that passes the rules but looks like a
coloured prototype fails this skill. The render has to hold up next to a shipped title, and
that is a short, checkable list:

1. **One sun, and the camera sees it.** A single directional key, 10–20° elevation, 30–50° off
   the view axis, so the surfaces you look at carry a gradient. Backlit silhouettes alone are a
   mood, not a lighting setup.
2. **A sky that is a function.** The dome, the ambient fill, the fog colour and the puddle
   reflections all call the same `skyColor()`. If the horizon is a different colour from the
   reflection, the scene disintegrates.
3. **Contact shadows.** Shadow map + AO. Objects that do not sit on the ground read as stickers.
4. **Atmosphere between you and the far plane.** Height fog, plus volumetrics if there is a sun.
5. **Surfaces with scale.** Every material carries wear, seams or aggregate — see
   `references/material-authoring.md`. One albedo per object is a placeholder.
6. **A linear pipeline with an sRGB encode at the end.** HDR buffer, ACES, grade, then encode.
   Skipping the encode is the number one reason a hand-written renderer looks like night.
7. **Motion everywhere.** Camera drift, walk bob, dust, a 1.5 s shake decay — see
   `references/game-feel.md`.
8. **A frame that reads in ten seconds.** Run the test at the end of
   `references/cinematic-look.md` before calling it done.

If the game is 2D, items 1–4 and 6 collapse into palette, light direction and a glow pass; the
rest still apply.

## Asset-craft gate (3D, non-negotiable)

The quality bar judges the *frame*. This gate judges the *objects in it*. Comparing two
single-file 3D games put the entire visual gap in the asset layer: the better one spent 645 KB
on generated geometry, a 130-entry named material library, runtime Canvas textures and
continuous skinning — while both had a complete post chain. A shipped 3D game meets all six:

1. **Inline the engine.** Use a minified inline 3D library for PBR, IBL, shadows, skinning and
   curve geometry. Hand-writing a renderer is only allowed once the asset layer is complete;
   never trade asset depth for dependency purity.
2. **No bare primitive is a finished asset.** Every visible object passes through a bevel, a
   curved surface (lathe / tube / extrude / spline), per-vertex displacement, or a generated
   texture. Boxes, spheres and capsules are intermediates.
3. **Bevel, normals, seams.** Hard surfaces get a bevel ≥ 0.02 world units; generated geometry
   recomputes normals; revolved meshes average the seam-ring normals.
4. **Named materials with generated maps.** ≥ 12 named surfaces, each with albedo +
   roughness + metalness (or equivalent shader channels), plus runtime-generated wear, seams
   and decals. Raw RGB triples passed into a draw call are not a material system.
5. **Continuous skinning.** Animated characters are one weighted skinned mesh, never one
   primitive per bone.
6. **Seeded, table-driven builders.** Object spec tables plus a builder with a named seed RNG,
   a transform stack and material lookup. `Math.random()` must not decide silhouettes.

Starters and in-progress scaffolds are exempt. A deliverable is not: the 3D ship gate is
`python scripts/check_single_file.py game.html --strict --craft`, which fails on missing
geometry craft, a missing material library, missing generated textures, or bones without
skinning. Evidence, per-rule implementations and the catch-up order live in
`references/asset-craft.md`.

## Workflow

### 1. Scope in one sentence

Write the sentence before the code: *"You move a craft, collect drifting orbs, avoid
shards, the run ends on contact."* If it needs two sentences, cut a mechanic. A single file
trades breadth for density — one loop, executed well, with a clear failure state and an
explicit restart.

Pick a mode:

| Mode | When | Reference |
| --- | --- | --- |
| 2D canvas | Puzzle, arcade, tile world, card, sim, RPG-ish | `references/procedural-art-2d.md` |
| 3D (WebGL2) | Space, driving, FPS/TPS, atmospheric scenes | `references/procedural-3d.md` |

### 2. Scaffold the shell

```bash
python scripts/scaffold.py --name "Orb Runner" --mode 2d --out ./orb-runner.html
python scripts/scaffold.py --name "Night Shift" --mode 3d --out ./night-shift.html
```

The scaffold already contains the shell described in `references/architecture.md`: design
tokens, boot screen, title layer, canvas, HUD, pause and game-over cards, input layer,
audio bus, save bus, error boundary, and a marked `GAME` block for the actual rules. Keep
the shell, replace the rules.

### 3. Build systems before content

Order matters. Each layer must be observable before the next is written:

1. Loop + resize + DPR + colour pipeline (nothing visible yet — verify with a debug readout).
2. Input intent (verify by moving a rectangle).
3. Scene machine (`boot → title → play → paused → over`).
4. Art primitives (verify by drawing a static scene).
5. Entities and collision.
6. Audio and HUD feedback.
7. Content: waves, levels, tables, dialogue.

A one-line debug HUD (`scene`, `fps`, `entities`, `errors`) after step 1 saves hours by
step 6. See `references/resilience-and-a11y.md`.

### 4. Light it like a shot, not like a test scene

Before adding content, spend one pass on the frame, in this order:

1. **Composition.** One foreground object, one subject, a skyline gap where the sun sets.
2. **Key light.** Pick the direction, then derive ambient, fog and rim from the same vector.
3. **Materials.** Five channels per surface (albedo, roughness, metal, height, AO), wear in
   primer → oxide order, seams at a physical plate size.
4. **Atmosphere.** Height fog first, volumetrics second.
5. **Post.** HDR → bloom → ACES → grade → sRGB encode. Check the encode before you touch
   exposure.

`references/cinematic-look.md` has the numbers and the failure each one prevents;
`references/material-authoring.md` has the surface half.

### 5. Make it feel alive

Cheap, high-yield, in this order: a 2–4px screen shake on impact, a short particle burst on
every state change, a 120ms scale-pop on the thing you just hit, a vignette, a two-note
audio tick on every action, an idle animation (breathing, bobbing) on anything alive. These
buy more perceived quality than polygon count. Every state change needs two channels —
`references/game-feel.md` is the table.

### 6. Persist and resume

Best score, progress and settings are separate keys. Version them, wrap every storage call
in `try/catch` (private mode throws), and never let a corrupt save block boot. See
`references/state-and-persistence.md`.

### 7. Audit before you ship

```bash
python scripts/check_single_file.py ./orb-runner.html --strict
python scripts/check_single_file.py ./night-shift.html --strict --craft   # 3D deliverable
```

The audit fails on external references, missing element IDs, missing `<title>`/viewport, a
missing error boundary, and — with `--craft` — missing 3D asset craft; it warns on size and
frame-budget risks. `--craft` is **mandatory** for a shipped 3D game; the format audit alone
cannot see primitive stacks or an RGB-only palette. Then walk
`references/release-checklist.md` — it is the ship gate, not a suggestion.

## What goes where

```
<style>   tokens → reset → layout → HUD → screens → panels → responsive → reduced-motion
<body>    canvas → HUD layer → screen layers → toast → fatal banner → debug node
<script>  helpers → storage → audio → input → renderer → entities → scenes → loop → boot
```

One IIFE. Small modules as plain functions and object literals, ordered so nothing is
referenced before definition. No classes needed unless state is genuinely per-instance.

## Anti-patterns

- **Loading a CDN "just for the prototype."** The prototype is the deliverable; a CDN turns
  a 1-file game into a 2-file game with a hard dependency on someone else's uptime.
- **Writing gameplay before the loop and resize handler.** Every later bug becomes a
  layout bug.
- **One giant `draw()` with gameplay inside it.** Separate simulation from presentation, or
  pausing, restarting and testing become impossible.
- **Random palettes at draw time.** Colours must be fixed per session — derive them once
  from a seed and store them.
- **`localStorage` without `try/catch`.** Private mode and quota errors throw; an unguarded
  call kills boot.
- **Shipping without a restart path.** A game that ends in a dead screen is a demo, not a
  game.
- **A scene made of untextured boxes under a flat ambient.** The fastest way to look like a
  placeholder. One sun, one wear mask, one seam grid — thirty minutes, entire difference.
- **A finished asset that is a box, sphere or capsule.** Bevel it, revolve it, displace it or
  texture it. A primitive used directly is an intermediate masquerading as an object.
- **An RGB triple as a material.** Albedo is one channel. No roughness, no wear, no seam means
  no scale — see `references/asset-craft.md`.
- **One primitive per bone.** Widening the parts to hide the joint gaps produces beads on a
  string; skin the mesh instead.
- **Writing a renderer to avoid an inline engine.** Zero runtime requests is the rule. A
  1.4 MB inline library is still one file, and buys PBR, IBL and skinning for free.
- **Writing linear radiance into the canvas.** No encode, no highlights, no colour. Two lines
  of transfer function stand between "night" and "dusk".
- **Tuning exposure to hide a lighting problem.** If the ground needs exposure 2.0, the sun is
  too low or the albedo is too dark. Fix the cause.
- **Bloom as a glow effect.** It is a lens artefact at 3–6% strength; at 40% the frame turns
  into fog.

## Handing off

Report the file path, its size, what was verified (audit output — **including the 3D
`--craft` result** — devices tested, frame budget observed) and the one thing you would
build next. The player only ever needs the single file — say so explicitly.
