# Single-File Game

A game you can email. One `.html` file, opened with `file://`, no server, no network, no
`assets/` folder. Every pixel is drawn by code, every sound is synthesized by code, every map
is generated by code.

The constraint is the point:

- **No asset pipeline** means no missing files, no 404s, no "it works on my machine".
- **No dependency graph** means the artifact is the deliverable — review it, diff it, ship it.
- **Procedural content** means one file can hold a large world at a small byte cost.
- **Offline by default** means it works on a plane, in a classroom, on a USB stick.

## Core rules

These are non-negotiable. Violating one breaks the format.

1. **One file.** All CSS in one `<style>`, all JS in one `<script>` IIFE. No `<link href>`,
   no `<script src>`, no `fetch`, no `import`, no web fonts. A 3D library, if you must, is
   pasted inline and minified — never referenced.
2. **Zero network at runtime.** Works with the network disabled. No telemetry, no analytics.
3. **Art is drawn, not loaded.** Canvas 2D calls, CSS gradients, SVG, or shader-generated
   textures. Bake expensive art once into an offscreen canvas, then blit.
4. **Audio is synthesized.** WebAudio oscillators plus a shared noise buffer. No audio files.
5. **Deterministic where it matters.** Seeded PRNG for maps, palettes and spawn tables so a
   seed reproduces a run; `Math.random()` only for cosmetic jitter.
6. **Failure is a feature.** A global error handler paints a readable banner and keeps the
   page inspectable. Never ship a silent black screen.
7. **Input parity from commit one.** Keyboard, pointer, touch and gamepad resolve into one
   intent object. Mobile is not a later milestone.

## Workflow

### 1. Scope in one sentence

Write the sentence before the code: *"You move a craft, collect drifting orbs, avoid
shards, the run ends on contact."* If it needs two sentences, cut a mechanic. A single file
trades breadth for density — one loop, executed well, with a clear failure state and an
explicit restart.

Pick a mode:

| Mode | When | Reference |
| --- | --- | --- |
| 2D canvas | Puzzle, arcade, tile world, card, sim, RPG-ish | `references/procedural-art-2d.md` |
| 3D (WebGL2) | Space, driving, FPS/TPS, atmospheric scenes | `references/procedural-3d.md` |

### 2. Scaffold the shell

```bash
python scripts/scaffold.py --name "Orb Runner" --mode 2d --out ./orb-runner.html
python scripts/scaffold.py --name "Night Shift" --mode 3d --out ./night-shift.html
```

The scaffold already contains the shell described in `references/architecture.md`: design
tokens, boot screen, title layer, canvas, HUD, pause and game-over cards, input layer,
audio bus, save bus, error boundary, and a marked `GAME` block for the actual rules. Keep
the shell, replace the rules.

### 3. Build systems before content

Order matters. Each layer must be observable before the next is written:

1. Loop + resize + DPR (nothing visible yet — verify with a debug readout).
2. Input intent (verify by moving a rectangle).
3. Scene machine (`boot → title → play → paused → over`).
4. Art primitives (verify by drawing a static scene).
5. Entities and collision.
6. Audio and HUD feedback.
7. Content: waves, levels, tables, dialogue.

A one-line debug HUD (`scene`, `fps`, `entities`, `errors`) after step 1 saves hours by
step 6. See `references/resilience-and-a11y.md`.

### 4. Make it feel alive

Cheap, high-yield, in this order: a 2–4px screen shake on impact, a short particle burst on
every state change, a 120ms scale-pop on the thing you just hit, a vignette, a two-note
audio tick on every action, an idle animation (breathing, bobbing) on anything alive. These
buy more perceived quality than polygon count. Concretely, see
`references/design-language.md` and `references/procedural-art-2d.md`.

### 5. Persist and resume

Best score, progress and settings are separate keys. Version them, wrap every storage call
in `try/catch` (private mode throws), and never let a corrupt save block boot. See
`references/state-and-persistence.md`.

### 6. Audit before you ship

```bash
python scripts/check_single_file.py ./orb-runner.html --strict
```

The audit fails on external references, missing element IDs, missing `<title>`/viewport, and
a missing error boundary; it warns on size and frame-budget risks. Then walk
`references/release-checklist.md` — it is the ship gate, not a suggestion.

## What goes where

```
<style>   tokens → reset → layout → HUD → screens → panels → responsive → reduced-motion
<body>    canvas → HUD layer → screen layers → toast → fatal banner → debug node
<script>  helpers → storage → audio → input → renderer → entities → scenes → loop → boot
```

One IIFE. Small modules as plain functions and object literals, ordered so nothing is
referenced before definition. No classes needed unless state is genuinely per-instance.

## Anti-patterns

- **Loading a CDN "just for the prototype."** The prototype is the deliverable; a CDN turns
  a 1-file game into a 2-file game with a hard dependency on someone else's uptime.
- **Writing gameplay before the loop and resize handler.** Every later bug becomes a
  layout bug.
- **One giant `draw()` with gameplay inside it.** Separate simulation from presentation, or
  pausing, restarting and testing become impossible.
- **Random palettes at draw time.** Colours must be fixed per session — derive them once
  from a seed and store them.
- **`localStorage` without `try/catch`.** Private mode and quota errors throw; an unguarded
  call kills boot.
- **Shipping without a restart path.** A game that ends in a dead screen is a demo, not a
  game.

## Handing off

Report the file path, its size, what was verified (audit output, devices tested, frame
budget observed) and the one thing you would build next. The player only ever needs the
single file — say so explicitly.
